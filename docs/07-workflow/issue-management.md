# Gestión de Issues

## Campos requeridos
- Título con verbo y resultado.
- Descripción y objetivo.
- Alcance y fuera de alcance cuando sea necesario.
- Checklist de subtareas.
- Criterios de aceptación observables.
- Fase.
- Milestone.
- Área.
- Prioridad.
- Responsable principal.
- Estimación.
- Dependencias.
- Evidencia de verificación.

## Estados
- Backlog: trabajo identificado pero no preparado.
- Ready: definido y listo para comenzar.
- In Progress: alguien está trabajando.
- In Review: espera revisión de PR o contenido.
- Testing: requiere validación funcional.
- Done: criterios cumplidos y cambios integrados.

Si una Issue está bloqueada, registrar el bloqueo en comentarios y, si es útil, añadir etiqueta `status:blocked`.

## Cuándo dividir una Issue
Dividir si contiene varios resultados independientes, requiere más de una especialidad o su estimación supera 6–8 horas. No dividir acciones triviales en Issues separados.
