# Gestión de riesgos

| Riesgo | Probabilidad | Impacto | Respuesta |
|---|---|---|---|
| Alcance mayor que capacidad de 4–8 semanas | Alta | Alto | Priorizar MVP, revisar avance semanal y aplazar P2. |
| Curva de aprendizaje de Three.js/Rapier | Alta | Alto | Prototipo pequeño, pairing y tareas acotadas. |
| Conflictos de integración | Media | Alto | Ramas por Issue, PR pequeños, integración frecuente y main estable. |
| Fuentes históricas incompletas o contradictorias | Media | Alto | Registrar variantes, contrastar y no inventar datos. |
| Derechos/condiciones de uso de imágenes y audio | Media | Alto | Registrar fuente y condiciones; sustituir recursos no utilizables. |
| Rendimiento móvil insuficiente | Alta | Alto | Probar temprano en hardware real, perfiles gráficos y simplificación. |
| Complejidad de siete NPCs | Alta | Medio/Alto | FSM sencilla, rutas predefinidas y optimización por distancia. |
| Retrasos por assets 3D | Media | Medio | Usar recursos simples y priorizar el recorrido sobre detalles. |
| Problemas de ruta/base en GitHub Pages | Media | Alto | Configurar y probar despliegue temprano, no al final. |
| Pérdida de tiempo por tareas ambiguas | Media | Alto | Criterios de aceptación y responsable único en cada Issue. |

## Revisión
Actualizar probabilidad, impacto, responsable y estado semanalmente. Todo riesgo alto debe tener una acción concreta y una persona responsable.
