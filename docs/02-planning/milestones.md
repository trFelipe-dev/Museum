# Milestones de GitHub

Crear ocho Milestones. Los hitos representan entregables, no fases. Una Issue se asigna al milestone que recibe el resultado de esa tarea, aunque su fase de trabajo sea otra.

| ID | Nombre | Resultado | Criterios de cierre |
|---|---|---|---|
| M01 | Preparación y prototipo técnico | Aplicación Vite/Three.js y movimiento desktop | Instalación reproducible, escena renderizada, cámara y movimiento en primera persona, colisiones básicas, guía local. |
| M02 | Prototipo multiplataforma | Controles táctiles del prototipo | Joystick, cámara táctil, botones y orientación probados en dispositivo acordado. |
| M03 | Prototipo museográfico funcional | Sala piloto con exposición y NPC de prueba | Sala, retrato, marco, placa, ficha de tres niveles, datos JSON y un NPC funcionan de principio a fin. |
| M04 | Construcción arquitectónica | Recorrido completo | Vestíbulo, núcleo, tres salas, reflexión/salida, circulación y colisiones conectadas. |
| M05 | Integración de la colección | Nueve exposiciones consultables | Nueve imágenes, placas, fichas y fuentes verificadas. |
| M06 | NPCs y ambiente | Museo poblado y sonoro | Siete NPCs con estados esenciales; audio y subtítulos/control de volumen conforme a alcance aprobado. |
| M07 | Optimización y pruebas | Versión candidata | Pruebas funcionales, móviles y rendimiento ejecutadas; errores bloqueantes resueltos; limitaciones documentadas. |
| M08 | Publicación y entrega | Museo público | Build de producción, Actions, Pages, smoke test y documentación final. |

## Reglas
- No crear milestones duplicados por fase.
- No fijar fechas de vencimiento hasta aprobar estimaciones y calendario.
- Cerrar un milestone únicamente cuando se cumplan sus criterios, no solo cuando todas las Issues estén cerradas administrativamente.
- Si se aplaza una funcionalidad P2, moverla a backlog futuro y documentar la decisión; no bloquear la entrega si no era criterio de aceptación.
